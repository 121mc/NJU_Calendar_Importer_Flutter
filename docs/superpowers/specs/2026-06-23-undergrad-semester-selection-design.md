# 本科学期选择与导入删除管理设计

## 背景

当前应用在恢复登录态或网页登录成功后，会自动拉取官方课表系统返回的当前学期课表。官方课表网页支持通过“更改”按钮切换学年学期，用户希望应用也支持选择本科可用学期后再主动拉取，并且同步覆盖与删除管理都能按学期边界工作。

本设计只覆盖本科生课表流程。研究生课表接口和现有研究生当前学期逻辑不在本次范围内。

## 已确认接口

本科官方课表页的学期能力来自现有本科接口：

- 当前学期接口：`/jwapp/sys/wdkb/modules/jshkcb/dqxnxq.do`
- 学期列表接口：`/jwapp/sys/wdkb/modules/jshkcb/cxjcs.do`
- 本科课表接口：`/jwapp/sys/wdkb/modules/xskcb/cxxszhxqkb.do`
- 本科期末考试接口：`/jwapp/sys/studentWdksapApp/WdksapController/cxxsksap.do`

`dqxnxq.do` 返回当前学期的 `DM` 与 `MC`，例如 `DM=2025-2026-2`、`MC=2025-2026学年 第2学期`。

`cxjcs.do` 返回可选学期列表。每项使用 `XN` 和 `XQ` 拼出应用内部学期编码：`semesterId = "$XN-$XQ"`。`XQ=1` 表示第 1 学期，`XQ=2` 表示第 2 学期，`XQ=3` 表示暑期。列表项还带有 `XQKSRQ` 和 `ZZC`，用于计算该学期开始与结束范围。

## 用户流程

登录成功或恢复登录态后，应用不再自动拉取当前学期课表。主页面显示：

1. 当前登录态卡片。
2. 新的“课表学期”卡片。
3. 仅在已经成功拉取且可导入日程数量大于 0 时显示“系统日历同步”卡片。
4. 永远在页面底部显示“删除本软件生成的日程”卡片。

“课表学期”卡片上半部分是本科可选学期下拉框。下拉框内容与官方网页保持同步，来自 `cxjcs.do`。默认选择 `dqxnxq.do` 返回的当前学期。如果当前学期不在列表中，回退选择列表第一项，并给出非阻断提示。

“课表学期”卡片下半部分是“拉取所选学期课表”按钮。用户点击后，应用按选中学期拉取课程和期末考试。只有最终可导入事件数为 0 时，应用弹窗提醒该学期暂无可导入课程或考试日程，并清空当前课表结果，因此不展示日历同步卡片。

## 数据模型

新增本科可选学期模型，包含：

- `id`：如 `2025-2026-2`。
- `name`：如 `2025-2026学年 第2学期` 或 `2025-2026学年 暑期`。
- `start`：来自 `XQKSRQ`。
- `end`：优先由 `start + ZZC 周 - 1 毫秒` 计算。
- `year` 与 `term`：保留原始 `XN`、`XQ`，方便接口提交与显示。
- `isCurrent`：是否匹配 `dqxnxq.do` 当前学期。

`ScheduleBundle` 增加：

- `semesterId`
- `semesterName`
- `semesterStart`
- `semesterEnd`

已有的 `courseCount`、`examCount`、`events` 保留。

## 拉取逻辑

`NjuScheduleService` 保留现有公开入口给研究生逻辑使用，同时新增本科专用能力：

- 获取本科可选学期列表。
- 获取本科当前学期并在列表中标记默认项。
- 按指定本科 `semesterId` 拉取课程与期末考试。

本科课程接口继续提交：

- `XNXQDM`
- `pageSize=9999`
- `pageNumber=1`

本科考试接口继续在 `requestParamStr` 中提交：

- `XNXQDM`
- `*order=-KSRQ,-KSSJMS`

日期展开使用所选学期的 `semesterStart`，不再默认使用当前学期。课程和期末考试都会进入最终事件列表。事件按开始时间排序。

## 日历写入标记

新写入事件使用新标记：

```text
[NJU_CALENDAR_IMPORTER]
semester_id=2025-2026-2
import_key=...
```

应用仍兼容识别旧标记：

```text
[NJU_SCHEDULE_IMPORT]
```

旧版事件没有 `semester_id`，但覆盖删除和独立删除管理都要识别它们。

## 覆盖删除

同步写入时，如果用户开启覆盖删除，应用只扫描当前目标日历中所选学期的起止范围：

- `rangeStart = bundle.semesterStart`
- `rangeEnd = bundle.semesterEnd`

如果官方学期结束范围异常，才回退到基于 bundle 中事件的范围。

删除匹配规则：

- description 包含新标记或旧标记。
- 新版事件带 `semester_id` 时，必须等于当前所选学期。
- 旧版事件没有 `semester_id` 时，只要落在所选学期时间范围内即可删除。

这样覆盖当前学期时不会删除其他学期的新格式事件，也不会漏掉同一学期旧版本导入的事件。

## 独立删除管理

“删除本软件生成的日程”从写入卡片中移出，永远作为主页面最底部的单独卡片展示。该卡片不依赖登录态、课表拉取结果或日历写入卡片是否展示。

点击后进入新的删除窗口。窗口会扫描本机可读取日历中所有包含新标记或旧标记的事件，并按以下方式分组：

- 有 `semester_id` 的事件按该 id 分组，例如 `2025-2026-2`。
- 没有 `semester_id` 的旧版事件放入“旧版本导入（未记录学期）”分组。

每组显示事件数量，并允许用户选择性删除。窗口底部提供“全部删除”按钮，用于删除扫描到的所有本软件生成事件。

如果系统只有写入权限，无法读取已有事件，删除窗口提示需要完整日历权限后才能扫描和删除。

## UI 状态

登录态存在但学期列表还没加载完成时，“课表学期”卡片显示加载状态。

学期列表加载失败时，保留登录态，并在卡片中提供重试按钮。

拉取课表时，下拉框和拉取按钮进入禁用/加载状态。

用户切换学期但尚未拉取时，清空当前 `_bundle`，隐藏“系统日历同步”卡片，避免用户误把旧学期结果写入日历。

成功拉取且事件数大于 0 时，展示同步卡片，并显示本次选择的学期名称、课程数量、考试数量与可导入事件数量。

## 测试计划

新增或更新测试覆盖：

- 本科学期列表解析：`XN`、`XQ`、显示名、暑期命名、开始结束时间。
- 当前学期默认选择：`dqxnxq.do` 的 `DM` 与 `cxjcs.do` 列表匹配。
- 指定学期拉取：课程接口和考试接口提交用户选择的 `XNXQDM`。
- 空学期行为：事件数为 0 时清空 bundle 并不展示同步卡片。
- 新写入标记：description 使用 `[NJU_CALENDAR_IMPORTER]` 并包含 `semester_id`。
- 覆盖删除：只扫描所选学期起止范围，并识别新旧标记。
- 覆盖删除：带其他 `semester_id` 的事件不删除。
- 覆盖删除：旧版无 `semester_id` 的事件在范围内会删除。
- 独立删除管理分组：按 `semester_id` 分组，旧版事件进入未记录学期分组，全部删除覆盖所有分组。

## 非目标

- 不改研究生接口与研究生拉课表流程。
- 不实现跨设备或服务器端课程缓存。
- 不自动迁移旧版日历事件的 description。
- 不自动选择或创建系统日历。
