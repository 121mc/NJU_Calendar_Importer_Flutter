## 已观察到的语法模式

### 1. 停课

```text
【停课】(第<周次>周 周<星期> <开始节次>-<结束节次>节) 发生临时停课
```

实例：

```text
【停课】(第2周 周五 1-2节) 发生临时停课
【停课】(第14周 周三 3-4节) 发生临时停课
```

### 2. 调整教室（改地点）

```text
【调课】(第<周次>周 周<星期> <开始节次>-<结束节次>节 <原教室>) 临时调整教室为(<新教室>)
```

实例：

```text
【调课】(第3周 周三 7-8节 教105) 临时调整教室为(新教207)
【调课】(第3周 周四 3-4节 仙Ⅰ-211) 临时调整教室为(幕府山慕燕滨江)
【调课】(第4周 周二 5-6节 新教-107) 临时调整教室为(补课教室待确认)
```

注意：新教室是自由文本，可能是标准教室名、校外地点，也可能是“补课教室待确认”之类的占位文本。

### 3. 调整教师

```text
【调课】(第<周次>周 周<星期> <开始节次>-<结束节次>节 <原教师或原教师工号列表>) 临时调整教师为(<新教师>)
```

实例：

```text
【调课】(第2周 周五 3-4节 赵宜萱) 临时调整教师为(贺伟)
【调课】(第12周 周四 9-10节 PX2207815,LS2409001,9908032,0308024,LS2409002,0308025,LS2409003,20200180160) 临时调整教师为(周依娜)
```

注意：括号中的原教师既可能是姓名，也可能是由半角逗号连接的多个工号，不能简单按逗号拆分整个字段。

### 4. 一个字段包含多个事件

同一教学班的多个事件直接用半角逗号连接，下一个事件从 `【` 开始：

```text
<事件1>,<事件2>,...
```

可靠的拆分边界是：

```regex
,(?=【)
```

不能直接使用 `split(',')`，因为教师工号列表本身也包含半角逗号。

实例：

```text
【停课】(第2周 周六 1-2节) 发生临时停课,【停课】(第2周 周六 3-4节) 发生临时停课
```

多事件的排列不保证按周次排序。例如“电化学测量方法01班”的四条事件依次为第 13、17、9、5 周。

## 建议的解析策略

1. 空字符串表示没有后续调课。
2. 先用 `,(?=【)` 拆成独立事件，保留原始顺序，但业务处理不要依赖该顺序。
3. 用开头标签 `【停课】`、`【调课】` 判定大类。
4. 对 `【调课】` 再根据固定短语 `临时调整教室为(`、`临时调整教师为(` 判定子类型。
5. 周次、星期和节次可以结构化解析；教师和教室字段应保留原始文本。
6. 对未知标签或未知“临时调整……为”类型保留原文并记录日志，不应直接丢弃。
7. 课程原始“时间地点”仍是学期常规安排；后续调课是指定周次的增量覆盖，不能用一次调课覆盖整学期。

建议的数据结构：

```text
ScheduleAdjustment {
  type: cancellation | roomChange | teacherChange | unknown
  week: int
  weekday: int
  startSection: int
  endSection: int
  originalValue: string?
  newValue: string?
  rawText: string
}
```
