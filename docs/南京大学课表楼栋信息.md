## 别名规范化

解析地点时，应先处理别名、字符差异和明显的录入错误。

| 原始名称或前缀 | 规范名称 | 说明 |
| --- | --- | --- |
| 仙I | 仙Ⅰ | 拉丁字母和罗马数字差异 |
| 仙一 | 仙Ⅰ | 中文数字别名 |
| 仙二 | 仙Ⅱ | 中文数字别名 |
| 费A | 费彝民楼A区 | 常用简称 |
| 费B | 费彝民楼B区 | 常用简称 |

| 生科A | 生科楼A区 | 院系楼分区 |
| 生科C | 生科楼C区 | 院系楼分区 |
| 科创A | 科创大厦A | 简称 |
| 南雍-东 | 南雍楼东 | 标点差异 |
| 南雍楼东 | 南雍楼东 | 完整名称 |
| 南雍-西 | 南雍楼西 | 标点差异 |
| 南雍楼西 | 南雍楼西 | 完整名称 |

| 教加数字 | 教学楼 | 鼓楼校区教室简称，例如教120 |

规范化只应用于楼栋识别，不应删除原始教室号。例如：

```text
费A-202  -> 费彝民楼A区 202
仙I-525  -> 仙Ⅰ 525
南雍-西353 -> 南雍楼西 353
蒙楼机房602，604，606 -> 蒙民伟楼 602、604、606机房
```

## 解析建议

地点处理建议分为三个阶段：

1. 从“时间地点”字段中分离星期、节次、周次和地点。
2. 根据校区分别匹配楼栋前缀，并应用别名规范化。
3. 保留房间号和场地说明，生成供人阅读的短地址以及供地图使用的精确链接。

推荐的数据结构：

```dart
class CampusLocation {
  const CampusLocation({
    required this.campus,
    required this.building,
    required this.room,
    required this.rawLocation,
    required this.mapUrl,
  });

  final String campus;
  final String? building;
  final String? room;
  final String rawLocation;
  final String? mapUrl;
}
```

日历中供人阅读的地点可以保持简短：

```text
南大仙林 仙Ⅰ-524
南大鼓楼 费A-202
南大苏州 苏教B204
```

精确地图 URL 应根据规范楼栋或校区的固定坐标生成，而不是依赖地图软件解析上述简称。没有楼栋坐标时，应回退到对应校区的坐标。

## 健壮性要求

- 保留原始地点文本，规范化结果不能覆盖原始数据。
- 先按校区匹配，同一简称在不同校区可能代表不同地点。
- 兼容中文和英文标点、全角和半角字符以及多余空格。
- 兼容一个字段包含多个教室或多个楼栋。
- 不要把房间号误认为楼栋名称的一部分。
- 对未知地点返回原文，不要阻止整份课表导入。
- 地图链接应使用预先确认的坐标，并按所用地图服务要求选择正确坐标系。
